# Source context and explicit abstention

`qualified-source-context-v1` adds a reader-boundary distinction between a complete
qualified point and a literal fragment whose consequential context is unavailable.
It is opt-in for newly frozen requests. Historical contracts and saved results are
retained; their two-field verifier receipts do not supply the new context judgment.

The demonstrated gap was a mechanically bound, unfinished conditional retained as
a substantive claim. The complete frozen target and saved initial/revised readings
were inspected. Existing literal binding established where words occurred; explicit
unknowns acknowledged the missing continuation; qualification/polarity checks did
not establish context sufficiency. A literal match cannot complete that proposition.
The responsible insertion point is the source reader and its shared verification
boundary, before fingerprint composition. No source expansion or profile-level
reinterpretation resolves this gap.

The reader now has two collections:

- `claims` retains the existing binding meanings, compiler and provenance.
- `abstentions` records a machine-authored ID, exact fragment, missing components
  and rationale, with source coordinates and producer provenance. It contains no
  invented proposition, polarity or adoption. It never compiles to an observation.

An answer with abstentions uses `needs_more_context`. It may retain complete claims
from the same window. All blocks remain available; punctuation and conditionals are
not code heuristics for incompleteness. Missing context is a semantic judgment.

The existing TypeSafe qualification/polarity questions and passage relevance
questions are reused unchanged. An independent context-sufficiency Noul uses the
existing contract meaning, complete declared source and pinned verifier model.
It runs in the same request, for every substantive claim, both before and after a
semantic revision. Missing or uncertain context judgments withhold diagnostic
eligibility even when the other fields pass. The existing .90 threshold is retained;
this implementation does not calibrate it or demonstrate verifier accuracy.

The bounded correction loop may explicitly move an ID from claims to abstentions;
it cannot silently drop IDs. Mechanical binding errors still permit one model-authored
retry per Flash stage. An abstention itself is not a binding error and never triggers
a retry. An all-abstention answer skips an empty verifier call. The saved
`context_eligibility` result distinguishes withheld candidates and abstained IDs.
Diagnostic eligibility does not grant production admission or replace the full
required-check policy.

`evaluation/source-context-contract/<fingerprint>/contract.json`. This is a contract
handoff, not an executable experiment input. Existing `remaining-five-*` commands

`source-context-prepare --from-input <completed-five-window-input> --base-dir <base>
--json` freezes those same five sources under the new contract and returns an exact
`source-context-run` command. Preparation validates source lineage, previous attempt
accounting, published deployment/prices and receipt compatibility without inference.
The prepared maximum is 30 new paid requests (20 Flash including binding retries,
10 TypeSafe), a $1.010565120 reservation and $1.02 execution ceiling. Including the
completed history, at most 62 paid requests and less than $2 in prior list-price
usage plus the new reservation are allowed. Historical local calls remain separately
accounted. No model, source collection, threshold or production admission changes.

`source-context-run --input <new-frozen-input> --check-only --base-dir <base> --json`
validates the freeze without writes or inference. Paid execution additionally

confirmed prices and both provider credentials. Results and the source review
packet expose context eligibility, withheld fields and abstention IDs. No additional
trial is executed during preparation.
